[P1.1] Default settings are prime shelf space. A dominant mobile OS controls the first screen, first tap, and first voice command. When it makes its own wallet, browser, or assistant the default, OS dominance becomes an unearned head start in adjacent markets. Most users keep pre-selected options, so a rival can be faster, more private, or cheaper and still lose because it never occupies the default position.
[P1.2] This is clearest with browsers and assistants. A competing browser may block trackers better, but if every link opens the gatekeeper’s browser unless the user digs into settings, the platform has not won on merit. The assistant wired to the button or voice trigger gets habit, data, and integration advantages no outside rival can match. A startup cannot out-engineer default inertia alone.
[P1.3] The rule does not ban the gatekeeper’s products. It does not require removal or equal promotion. It only prevents the platform from reserving default status for itself. A neutral choice screen or genuine default-selection mechanism can preserve security and integration while making the default contestable.
[P1.4] That removes a distribution bottleneck, not a legitimate product feature.
[P1.5] The opt-out defense misses how choice architecture works. Users can change defaults, but the harm occurs before they try: the pre-selected service is presented as normal and trusted, and friction keeps it in place. If pre-checked boxes are understood as steering, a dominant OS pre-selecting its own wallet, browser, or assistant is steering at far greater scale.
[P1.6] AI assistants make the stakes urgent. Default assistants gain habits, queries, and integration that improve the product and lock users in before rivals can reach scale. Without a bar on self-preferencing, the next major interface will be decided by setup screens, not competition. The rule forces gatekeepers to compete on product quality instead of platform ownership.
