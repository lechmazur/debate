[P1.1] Predictive policing systems built on historical arrest and incident data don't predict crime. They predict where police have already chosen to look. That distinction isn't a technical quibble—it's the reason cities should prohibit them.
[P1.2] Arrests don't materialize where crime happens; they happen where officers are deployed, stop people, and make arrests. If a department patrols one neighborhood aggressively and another lightly, the arrest data will show "crime" concentrated in the first—not because more crime occurs there, but because that's where policing produces a recordable outcome. Feed that data into a predictive model and it returns the same answer: send more officers to the same neighborhood. More patrols generate more stops, more arrests, more entries confirming the original prediction.
[P1.3] The system doesn't learn about crime; it learns about itself.
[P1.4] This feedback loop falls hardest on communities already subject to intensive policing—disproportionately poor and minority neighborhoods. What gets framed as objective, data-driven deployment is the laundering of past enforcement choices into future enforcement mandates. The algorithm gives discretionary policing the veneer of neutral science.
[P1.5] You cannot fix this by tuning the model. The input is structurally biased: it measures police contact, not criminal victimization. A system that confuses its own output for ground truth will always reproduce the gap. And because the recommendation engine drives officer placement, the bias isn't passive—it actively concentrates state intrusion in the same places year after year.
[P1.6] The problem compounds because the system hides discretionary choices behind mathematical output. When residents ask why their block is saturated with patrols, the department points to the model. When asked what the model measures, the answer is—arrests from past patrols. The circle closes without anyone owning the decision.
[P1.7] Cities should prohibit these systems because the core design is defective in a way no accuracy metric can capture. A tool that converts historical over-policing into future over-policing shouldn't be refined. It should be removed.
