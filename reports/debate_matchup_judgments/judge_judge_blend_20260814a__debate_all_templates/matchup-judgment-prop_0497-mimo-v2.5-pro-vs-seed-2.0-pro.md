### Judge Notes

- **Gemini 3.1 Pro Preview** (A = Xiaomi MiMo V2.5 Pro (PRO); B = ByteDance Seed2.0 Pro (CON)): Side B won by exposing a critical flaw in Side A's proposal: software is not a static object like a book, meaning a usable deposit requires stripping DRM, mapping dependencies, and providing source code. Side A conceded that archives might demand source archives, which proved Side B's point about severe compliance burdens. Additionally, Side A suffered a major execution penalty by being clipped for exceeding the word limit in every single substantive speech.
  Most decisive rebuttal noted: Side B's first rebuttal cleanly dismantled Side A's "app store" comparison by pointing out that app store binaries are DRM-wrapped and server-dependent, meaning a usable archive copy would require days of uncompensated labor to decouple.
- **Grok 4.5 (high)** (A = Xiaomi MiMo V2.5 Pro (PRO); B = ByteDance Seed2.0 Pro (CON)): CON built the clearer path to victory by making the decisive technical clash stick: legal deposit completes almost nothing for software (unlike books), produces dead binaries, performs preservation, and risks crowding out working voluntary efforts, while PRO's authority-as-prerequisite claim never fully neutralized the incompleteness or the "cargo cult" failure mode. Multiple clipped A turns and incomplete closings compounded the comparative weakness despite solid cultural framing.
  Most decisive rebuttal noted: B's core rebuttal that file deposit is ~1% of software preservation (vs ~99% for books), creating vaults of unusable binaries and a false policy solution.
- **Kimi K2.6** (A = ByteDance Seed2.0 Pro (CON); B = Xiaomi MiMo V2.5 Pro (PRO)): CON (A) won by proving that legal deposit is structurally mismatched to software: depositing a static file completes preservation for books but leaves software as a dead binary without any promised funding for emulation, dependencies, or runtime reconstruction. PRO (B) never closed the gap between acquiring files and actually keeping them functional, conceded that no law can guarantee permanent funding, and relied too heavily on a book-analogy that CON had already dismantled. CON also landed a sharper compliance-burden distinction and a novel state-power objection, while PRO’s closing misrepresented CON’s answer to a pressure question and suffered multiple clipped speeches.
  Most decisive rebuttal noted: CON’s first rebuttal [A2], which introduced the 99%-vs-1% preservation distinction and detailed the DRM, dependency, and standalone-build burdens that make software deposit radically unlike book deposit, forcing PRO onto abstract defensive ground for the rest of the debate.

### Judge Notes

- **Gemini 3.1 Pro Preview** (A = ByteDance Seed2.0 Pro (PRO); B = Xiaomi MiMo V2.5 Pro (CON)): Side A won by effectively framing the debate as a choice between imperfect preservation and total erasure. Side B built a strong technical case that software requires an ecosystem, but overextended by arguing that archiving source code is functionally equivalent to total loss. Side A successfully absorbed Side B's technical attacks by conceding imperfection and maintaining that 'a chance is better than zero,' making Side B's perfectionism look unreasonable.
  Most decisive rebuttal noted: Side A's Rebuttal 2 decisively neutralized Side B's technical offensive by embracing the imperfection of the policy: 'Nobody is pretending this will work flawlessly... We do not get to choose between perfect preservation and nothing.'
- **Grok 4.5 (high)** (A = ByteDance Seed2.0 Pro (PRO); B = Xiaomi MiMo V2.5 Pro (CON)): PRO built the cleaner path to victory by making the decisive comparative choice unavoidable: imperfect deposit of source/docs (a non-zero chance of future reconstruction under existing legal-deposit machinery) versus near-total erasure under status quo. CON landed sharp, technically grounded points that software is not a self-contained artifact and that deposit can be illusory or diverting, but never fully neutralized the live “chance better than zero” route or the historical precedent that imperfect systems for films/books still justified the mandate. Clipping on two CON turns and residual reliance on voluntary fragility claims further limited B’s ability to close. A’s framing made the debate easier to decide.
  Most decisive rebuttal noted: A’s R2 answers plus crystallization (chance/reconstruction vs total loss; imperfect film deposit still correct) neutralizing B’s “inert files” and speculative-utility pressure.
- **Kimi K2.6** (A = Xiaomi MiMo V2.5 Pro (CON); B = ByteDance Seed2.0 Pro (PRO)): CON won by proving that software is ontologically distinct from books and films. Legal deposit succeeds for static, self-contained artifacts, but deposited source code without its operational ecosystem does not preserve the actual cultural artifact. PRO repeatedly conceded that deposited material would be non-functional, offering only "a chance, however distant" that emulation might someday bridge the gap. This admission collapsed the central analogy and left PRO arguing for an expensive filing exercise rather than genuine preservation. CON sharpened the comparative clash by showing the mandate would create false political comfort while diverting resources and attention from the volunteer technical communities that have actually kept software alive.
  Most decisive rebuttal noted: CON's rebuttal of the book/film analogy across Rebuttal 1 and Rebuttal 2, which showed that a book on a shelf is a preserved book whereas source code on a shelf is only an inert recipe without ingredients, exposing that PRO's plan preserves the illusion rather than the substance of cultural software.
